# The scope-scan exemption registry.
#
# HATCHES.txt's structure, one language over, with one thing added that the Go
# side does not have yet and that this file has from its first line: EVERY ENTRY
# CARRIES A SPLIT LABEL.
#
#   covered-by: <instrument>
#       The class this rule catches is caught here instead, by something that
#       EXISTS TODAY. The scan checks the named path exists; naming a future
#       instrument is how a registry rots.
#
#   unreachable: <detector> ~ <argument>
#       The thing the rule catches cannot occur here. <detector> is what would
#       have seen it if it did, and <argument> says why no other detector sees
#       this class more often. Both fields required.
#
# WHY TWO LABELS AND NOT A REASON FIELD. Track A spent a full cycle re-deriving
# seventeen single-labelled opt-outs and found three of them wrong, one a
# first-tier safety defect. A free-text reason lets "this is fine, something
# else covers it" and "nothing checks this and I have decided that is
# acceptable" wear identical clothes. The split forces the second one to say so
# out loud, and it makes the whole registry re-checkable by reading one column.
#
# AN UNUSED ENTRY FAILS THE LANE. A drifted hatch means something is unguarded
# while its author believes otherwise, and that is worse than no hatch: the
# registry is read as the list of known gaps, so a stale line makes a real gap
# look accounted for.
#
# Format, pipe-separated:
#
#   <rule-id> | <file> | <the exact offending line, trimmed> | <label>
#
# Anchored on the LINE TEXT rather than the line number on purpose. A line
# number goes stale on any edit above it and turns this lane into noise, and a
# noisy lane is a lane that gets weakened. Anchoring on the text means editing
# the exempted line un-registers it and forces the exemption to be re-argued,
# which is the sensitivity we want.
